# Участие в разработке Yamuse

Yamuse — неофициальный клиент Яндекс Музыки для Windows на C# и WPF. Перед участием ознакомьтесь с [правилами общения](CODE_OF_CONDUCT.md).

## Ошибки и предложения

Проверьте существующие обращения и [README](README.md). Для ошибки используйте форму **«Ошибка в Yamuse»**, для предложения — **«Предложение»** в [Issues](https://github.com/senduora/yamuse/issues). Описывайте один воспроизводимый случай или одну идею в одном обращении.

Укажите версию Yamuse, версию Windows и способ запуска: установленная версия, Portable или сборка из исходников. Для ошибок интерфейса полезны масштаб экрана, размер окна и обезличенный снимок. Сообщения о доступности оформляйте как обычные ошибки; рекомендации перечислены в [ACCESSIBILITY.md](ACCESSIBILITY.md).

Не прикладывайте файлы входа, токены, cookies, заголовки авторизации, полные личные журналы или скачанную музыку. Об уязвимостях сообщайте приватно по [SECURITY.md](SECURITY.md).

При отключённых Issues приём обращений через эти формы недоступен. Публичный pull request не подходит для передачи секретов или подробностей уязвимости.

## Среда и структура

Нужны Windows 10/11 x64, Git и .NET 8 SDK с поддержкой сборки WPF.

- `src/YMusic.Native` — приложение.
- `tests/YMusic.Native.Checks` — исполняемый набор проверок.
- `tools/packaging` — упаковка установщика и обновлений.

## Сборка и проверки

Из корня копии репозитория:

```powershell
dotnet restore src/YMusic.Native/YMusic.Native.csproj --locked-mode
dotnet restore tests/YMusic.Native.Checks/YMusic.Native.Checks.csproj --locked-mode
dotnet build src/YMusic.Native/YMusic.Native.csproj -c Release --no-restore
dotnet run --project tests/YMusic.Native.Checks/YMusic.Native.Checks.csproj -c Release --no-restore -- work/check-results
```

Набор проверок запускается через `dotnet run`, а не `dotnet test`. Проверки используют тестовые ответы, аудиофайлы и временные папки; они не подтверждают работу с реальным аккаунтом или фактическую установку обновления.

Для ручной проверки приложения:

```powershell
dotnet run --project src/YMusic.Native/YMusic.Native.csproj -c Release
```

Вход в аккаунт выполняйте самостоятельно. Не переносите cookies или токены из официального клиента и не добавляйте личные данные в тестовые фикстуры.

Для изменений интерфейса проверьте затронутый сценарий с клавиатурой, видимость фокуса и отображение при используемом масштабе Windows. Для изменений данных, очереди, авторизации, обновления или удаления отдельно опишите проверку сохранности данных и способ восстановления. Используйте изолированный тестовый профиль, когда сценарий меняет пользовательские данные.

## Pull request

1. Создайте fork и отдельную ветку от актуального `main`.
2. Ограничьте изменение одной задачей. Сохраните существующий стиль C# и XAML; не включайте попутное форматирование.
3. Добавьте проверку, если меняется логика или исправляется воспроизводимый дефект. Для текста и других малых правок достаточно подходящей проверки результата.
4. Приложите результат команд, сведения о среде и ручных сценариях. Отдельно укажите, что не проверено.
5. Для видимых изменений добавьте обезличенные снимки. Не включайте `bin`, `obj`, результаты проверок, установщики и пользовательские файлы.
6. Заполните шаблон PR: проблема, итоговое поведение, проверка и риски.

Если меняются зависимости или источники заимствованного кода, укажите происхождение, версию и лицензию. Не добавляйте их без необходимости.
